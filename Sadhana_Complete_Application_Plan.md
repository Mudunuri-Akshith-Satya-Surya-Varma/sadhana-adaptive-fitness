# SĀDHANĀ — Complete Application Plan

> **Sādhanā** is an adaptive AI fitness platform that understands the individual, assigns an appropriate training specialization, dynamically generates workouts according to the user's real-world circumstances, and continuously develops the user's fitness through performance, feedback, progressive challenge, and RPG-style progression.

---

# 1. Problem Statement

Most existing fitness applications provide standardized workout plans or assume that users have consistent schedules, sufficient time, appropriate equipment, and the discipline to follow fixed routines. In reality, people have different fitness levels, goals, experience, schedules, available resources, and changing day-to-day circumstances. When these conditions change, rigid fitness plans often become difficult to follow, causing users to lose consistency and eventually abandon their routines.

There is therefore a need for a fitness platform that can understand the individual user, determine an appropriate training direction based on their goals and current capabilities, and continuously adapt their workouts to their real-life circumstances without unnecessarily lowering the standard of progress. The system should account for factors such as available time, equipment, previous performance, workout history, preferences, and legitimate physical limitations while maintaining consistency and progressively challenging the user.

Sādhanā addresses this problem by combining rule-based fitness classification with AI-driven workout personalization and continuous adaptation, creating a fitness experience that adapts to the person while continuously developing their potential.

It accomplishes this through:

- Rule-based fitness classification
- AI-driven workout personalization
- Dynamic daily workout generation
- Continuous adaptation
- Performance tracking
- Progressive challenge
- RPG-style class progression
- Motivation and achievement systems

## Core philosophy

> **Adapt to the person. Challenge the person. Develop the person.**

Another core principle:

> **Adapt to the person. Never compromise the potential.**

# 4. Fitness Model

Sādhanā separates:

- Fitness components
- Classes
- Workouts
- Progression

These are different concepts.

## Five fundamental fitness components

1. Cardio-respiratory fitness
2. Strength
3. Flexibility
4. Balance
5. Coordination

Every Sādhanā Class contains the **basic and necessary level of all five**.

The Class determines where the system goes deeper.

```text
FITNESS
   ↓
Common fundamentals
   ↓
Specialization
   ↓
Individual development
```

This is similar to:

```text
CSE
 ↓
Common fundamentals
 ↓
AI/ML
Cybersecurity
Data Science
```

All specializations belong to CSE, but each goes deeper into a specific area.

Similarly:

```text
FITNESS
 ↓
Cardio
Strength
Flexibility
Balance
Coordination
 ↓
Sādhanā Classes
```

A Yodha (Strength) user still needs flexibility, balance, coordination and cardio.

A Vistāra (Flexibility) user still needs strength and cardiovascular support.

A Sthira (Balance) user still needs strength, flexibility, and coordination.

Therefore:

> **Class ≠ Component ≠ Workout**

- **Components** = physical abilities being developed.
- **Class** = assigned training specialization/discipline (Sthira, Vistāra, Yodha, Dhruva, Samanvaya).
- **Workout** = actual training generated for the individual.
- **AI** = how those abilities are developed for that individual.
- **Consistency** = universal principle.
- **Mental wellbeing** = universal principle.
- **RPG progression** = motivation and long-term development layer.

# 5. Sādhanā Classes

Sādhanā assigns users to one of **five core Classes**, representing the primary physical discipline of their current training journey:

| Class | Sanskrit Identity | Core Specialization & Focus | Underlying Domain |
|---|---|---|---|
| **Sthira** | स्थिर (Steady / Firm) | **Balance**, core stability, body control & postural poise | Balance |
| **Vistāra** | विस्तार (Expansion) | **Flexibility**, movement quality, range of motion & mobility | Flexibility |
| **Yodha** | योद्धा (Warrior) | **Strength**, resistance development & muscular power | Strength |
| **Dhruva** | ध्रुव (Steadfast) | **Cardio / Endurance**, stamina & aerobic conditioning | Cardio / Endurance |
| **Samanvaya** | समन्वय (Coordination / Harmony) | **Coordination**, agility, multi-planar athletic performance & speed | Coordination |

## Class philosophy

Each Class is a **specialization**, not a restriction.

Every Sādhanā Class contains the **basic and necessary level of all five fundamental disciplines**. The assigned Class determines where the system goes deeper:

For example:

```text
YODHA (STRENGTH CLASS)
████████████████████  Primary: Strength (Yodha)
██████████           Supporting: Cardio / Endurance (Dhruva)
██████████           Supporting: Flexibility (Vistāra)
████████             Supporting: Balance (Sthira)
████████             Supporting: Coordination (Samanvaya)
```

Similarly, for Sthira:

```text
STHIRA (BALANCE CLASS)
████████████████████  Primary: Balance (Sthira)
██████████           Supporting: Strength (Yodha)
██████████           Supporting: Flexibility (Vistāra)
████████             Supporting: Coordination (Samanvaya)

```

The exact training proportions are determined by the adaptive training system and individual daily context.

# 6. Physical Disciplines & Class Identities

The five Classes correspond directly to the foundational disciplines of human movement:

1. **Sthira (Balance / Stability)**: Proprioception, unilateral strength, core control, and stabilizing endurance.
2. **Vistāra (Flexibility / Range of Motion)**: Joint health, fascia release, active and passive mobility, and movement freedom.
3. **Yodha (Strength / Power)**: Progressive overload, mechanical tension, muscle development, and explosive force.
4. **Dhruva (Cardio / Endurance)**: VO2 capacity, work capacity, cardiovascular health, and physical stamina.
5. **Samanvaya (Coordination / Athleticism)**: Kinetic chain sequencing, speed-agility, neurological control, and multi-skill execution.

A user assigned to **Yodha** develops their character through strength challenges while maintaining the health of all other disciplines. A user assigned to **Dhruva** builds an aerobic engine while preserving strength, balance, and mobility.

# 10. RPG Progression Must Be Based on Real Training

Sādhanā should avoid a system where users simply farm points.

Progress can be influenced by:

- Completing workouts
- Maintaining consistency
- Completing challenging sessions
- Improving performance
- Completing Class-specific challenges
- Reaching meaningful milestones
- Following training targets
- Demonstrating improvement

The principle is:

> **Rewards should reinforce fitness behaviour, not replace it.**

A user should not be able to exploit the system by repeatedly doing extremely easy workouts only to gain levels.

# 14. Dynamic Workout Model

Sādhanā should **not generate seven fixed workouts every Monday**.

It uses a hybrid system.

## Weekly plan = direction

The weekly plan defines targets such as:

```text
Strength: 3 sessions
Cardio: 2 sessions
Mobility: supporting work
Recovery: appropriate spacing
```

The weekly plan is a **training direction**, not necessarily a rigid schedule of seven exact workouts.

## Daily workout = execution

```text
Weekly Direction
       +
Today's Situation
       ↓
AI
       ↓
Today's Workout
```

Today's situation may include:

- Available time
- Available equipment
- Previous workout
- Actual duration
- Completion
- Performance
- Feedback
- Difficulty
- Recovery/context
- Current goal
- Class
- Progression level

---

# 15. Adaptive Workout Example

Suppose:

```text
Planned workout = 30 minutes
Actual workout = 22 minutes
```

Sādhanā records:

```text
planned_duration = 30
actual_duration = 22
completion_status = incomplete
reason = time constraint
```

It does not simply say:

> “Tomorrow = 38 minutes.”

Instead, the next workout is generated using the updated context and weekly direction.

If the user has another 20-minute window tomorrow:

```text
20-minute focused workout
```

may be generated.

The system tries to preserve the training objective rather than mechanically carrying missing minutes forward.

---

# 16. Adaptation Does Not Mean Making Everything Easier

This is one of Sādhanā's defining principles.

## Legitimate constraint

```text
Only 20 minutes available
No equipment available
Unexpected schedule change
Physical discomfort
```

→ **Adapt.**

## Avoidable resistance

```text
"I don't feel like it."
"I just don't want to."
```

→ Encourage completion rather than automatically lowering the standard.

Therefore:

> **Sādhanā is adaptive, not permissive.**

# 17. Optimal Challenge System

The AI should evaluate whether the user is being challenged appropriately.

```text
                 USER PERFORMANCE
                        ↓
                Challenge Analysis
                        ↓
          ┌─────────────┼─────────────┐
          ↓             ↓             ↓
       Too Easy     Appropriate    Too Difficult
          ↓             ↓             ↓
     Increase        Maintain       Adjust
     challenge       / progress     difficulty
```

If there is potential physical risk:

```text
Pain / concerning discomfort
            ↓
      Stop / modify
            ↓
  Appropriate guidance
```

Sādhanā should not diagnose medical conditions.

# 34. AI Safety and Control

Gemini should **not have unrestricted authority**.

Django validates:

- Exercise IDs
- Duration
- Number of exercises
- Sets/reps ranges
- User ownership
- Class compatibility
- Required fields
- JSON structure
- Database relationships
- Progression boundaries

The application should not present Gemini as a medical professional.

For concerning pain/injury feedback, the system can recommend stopping/modifying the activity and seeking appropriate professional evaluation rather than diagnosing the condition.

# 53. Authentication & User Journey Architecture

## 53.1 Multi-User Isolation Model
- **User Identity**: Managed via `django.contrib.auth.models.User` (unique username, unique email, salted PBKDF2 password hashes).
- **Profile Binding**: 1:1 `UserProfile` containing personal biometrics, assigned discipline class, equipment access, limitations, RPG level, XP, and Aura.
- **Authentication Standard**: Django REST Framework Token Authentication (`rest_framework.authtoken`), supporting stateless token management in SPAs with `Authorization: Token <key>`.

## 53.2 User Onboarding & Auth Journey
```text
NEW PRACTITIONER:
  1. Register Page (/register) -> Credentials & Account Creation (Name, Username, Email, Password)
  2. Auto-login -> Biometric Evaluation (/onboarding) -> Baselines, Intentions, Equipment, Health
  3. Deterministic Classifier -> Cinematic Discipline Reveal (/reveal)
  4. Active Practice Dashboard (/today) -> 100% Tailored Equipment & Discipline Workouts

RETURNING PRACTITIONER:
  1. Sign In Page (/login) -> Enter Username or Email + Password
  2. Instant Restoration -> Active Class, Level, Aura, and Dynamic Practice (/today)

DEMO / REVIEW MODE:
  1. One-Click Demo Practitioner ("Arjun" • Yodha LVL 1) for zero-friction evaluation.
```
